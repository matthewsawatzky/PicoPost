Server setup

PicoPost is a single Go binary plus a SQLite file. No Docker, no Postgres, no Redis. This page walks you through installing and configuring it.

1. Install

The install script downloads the latest release for your platform and places the picopost binary in ~/.local/bin (or ~/bin if that exists).

curl -fsSL https://raw.githubusercontent.com/matthewsawatzky/PicoPost/main/install.sh | sh

Or build from source (requires Go 1.22+):

git clone https://github.com/matthewsawatzky/PicoPost.git
cd PicoPost
go build -o bin/picopost ./cmd/picopost

2. Configure

Create picopost.toml. The example below is the full default configuration — copy it and adjust the parts that matter to you.

[server]
listen = "127.0.0.1:8080"

[storage]
database = "./data/picopost.db"

# Origins allowed to call the API from browsers.
# Use ["*"] for a deliberately public mode.
[cors]
origins = [
  "https://example.com",
  "https://your-site.pages.dev"
]

[posts]
max_body_bytes = 1024
max_text_bytes = 768
max_metadata_bytes = 256
max_metadata_keys = 16
max_key_length = 32
max_urls_per_post = 5
page_size = 50

[identity]
anonymous = true
browser = true

[rate_limit]
posts_per_minute = 20
# Only trust X-Forwarded-For when behind a reverse proxy that
# overwrites it. Never enable on a public port.
trust_forwarded = false

[filters.username]
deny = ["admin", "administrator", "moderator", "system"]

[filters.text]
deny = ["blocked phrase", "spam.example"]

3. Run

picopost serve --config ./picopost.toml

Validate the configuration and database without starting the server:

picopost check --config ./picopost.toml

4. Put it behind a reverse proxy

PicoPost listens on localhost by default. In production, put it behind Caddy, nginx, or Cloudflare Tunnel so it gets TLS and a public hostname.

Example Caddyfile:

posts.example.com {
    reverse_proxy 127.0.0.1:8080
}
If your proxy rewrites X-Forwarded-For, set trust_forwarded = true in [rate_limit] so rate limiting sees real client IPs. Never enable it when the port is directly reachable from the internet.

5. Serve the client and demo

PicoPost itself only serves the API. Serve picopost.js and the demo site from any static host — Cloudflare Pages, GitHub Pages, nginx, or the same proxy.

# Serve the whole web/ directory (client + demo + docs site)
caddy file-server --root ./web --listen :8081

6. Deploy the docs/demo site to Cloudflare Pages

The web/site/ folder is a static site ready for Cloudflare Pages. Connect your repo and set:

SettingValue
Build commandnone (it is already static)
Build output directoryweb/site

Or deploy with Wrangler:

npx wrangler pages deploy web/site
The demo page talks to a PicoPost server. Point it at your own instance with the server box on the demo page, or run a public instance and add your Pages origin to its [cors] origins.

7. Development

Clone the repo and use the ./dev helper — it builds, starts the API plus a local demo site, and manages the dev database.

./dev start      # API on :8080, demo site on :8081
./dev status     # what is running, health, database state
./dev logs       # follow logs
./dev db clean   # reset the dev database
./dev test       # run the test suite
./dev stop

8. What you get

FeatureDetails
Poststext + optional JSON metadata, max 1 KB by default
Channelsvalidated strings like chat/general — no per-feature code
Identitieslightweight browser identities, not user accounts
Live updatesSSE, in-process broadcaster
Filtersdeny lists for usernames and text, URL counting
Rate limitingper-IP, in-memory, configurable
StorageSQLite, one file, automatic migrations
